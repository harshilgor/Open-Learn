# In-Class mode implementation

Implemented on 4 October 2026 against the existing Python/React application. The web feature reuses lecture capture/transcription, the durable agent worker, course/Buddy attribution, QuizService, shared artifact storage, and the responsive study canvas. It does not provision Supabase or replace the native recording adapter.

## Current extension status — 5 October 2026

The implementation now includes caption-grounded provisional drafts, course-library cue lookup, material-v2 page/cue/term indexing and optional vector reranking, resumable OCR, desktop lifecycle controls, mobile capture and metadata compaction. See `docs/IN_CLASS_COMPLETION_STATUS.md` for current behavior and acceptance evidence. Historical descriptions below document the earlier foundation; where they say a feature remains open or captions do not generate notes, the completion report supersedes that limitation.

## Start and revisit

Choose In-Class from the conversation mode menu or Start class session from a course. The explicit conversation request “Start taking notes for this class” opens the same setup. Opening setup never starts a microphone. Select the course, Buddy override, title, available course materials, microphone where the browser enumerates multiple inputs, detail/audio preferences, and quiet output preferences. Consent must be checked before Start listening is enabled.

On Windows desktop, a separate optional control can include computer audio. The native picker requires a user gesture and offers the current screen/window sources; Electron grants loopback audio only to the trusted app origin and main frame. The temporary display video track is stopped immediately when returned, and only microphone/system audio is mixed into the locally persisted slices. The session records whether computer audio was enabled. Computer audio may include sound from other apps; live captions disclose when the mixed audio is sent to the configured provider. This flow has not yet received real-device acceptance.

The desktop capture shell uses an origin-checked Electron bridge to prevent display sleep while recording, after the existing recording permission has been granted. It releases the blocker on pause, stop, renderer loss, navigation teardown, window close, and app quit, and announces whether the display is being kept awake. This prevents display sleep; it does not wake a sleeping machine or add lock-screen/tray controls, and has not been checked in a packaged desktop build.

The start gesture requests microphone access before a long server operation. Denial leaves no recording manifest and shows the failure in setup. Successful capture saves an owner-labelled manifest and independent audio slices locally. A stable recording ID is reused when the API becomes available. Setup resolves the explicit Buddy override, course Buddy, then account default, and creates one class envelope, recording note, and linked conversation. Setup retries reuse those identities; a changed device/setup is rejected.

Live captions are optional and off by default. The setup control appears only when the server enables `OPENLEARN_CLASS_LIVE_TRANSCRIPTION_ENABLED` and has an OpenAI API key. Checking it explicitly sends microphone audio—or microphone plus computer audio when that option is enabled—to an OpenAI transcription-only Realtime session over WebRTC; the server mints a short-lived client credential only after the authenticated owner presents a high-entropy capability generated for that capture. The capability is stored in the local recording manifest, hashed in the class record, and omitted from snapshots and exported manifests. Client-side voice detection commits caption turns after a pause or a bounded continuous-speech interval. Each finalized turn is posted with a stable stream ID, sequence, provider item ID, and approximate recording-relative VAD interval; the server validates these optional bounds, stores them in `class_live_transcript_segments`, then publishes a replayable class event. Timing uses 100 ms VAD samples and the provider commit boundary, so it is not word-level alignment. A reconnect retries unpersisted turns held by the current page. The class snapshot exposes the latest 100 saved provisional turns. If setup or streaming fails, a Retry captions control can reconnect without restarting audio capture. Stop captions, pause, Stop, or account change closes the caption stream and audio-analysis context while local durable slice capture remains independent. These saved provisional captions are separate from the authoritative transcript and do not yet feed note coordination. Existing batch transcription of archived slices still runs separately and remains authoritative, so the optional path adds provider usage. Tier-1 note generation and final transcript reconciliation remain open.

If “Keep class audio for playback” is off, local recovery copies remain until upload and transcription complete, then the server objects are removed while notes and transcript remain. Deletion is retried from finalization/status paths if the object store is temporarily unavailable. A completed recording also offers “Delete audio, keep notes”; this owner-authorized action requires confirmation and removes only the audio objects. Audio retention state is returned with the recording status so the UI does not claim removal while cleanup is pending.

## NeedInfo source intake

When retrieval cannot find a useful passage, the NeedInfo card can use an eligible ready library item, import a public URL, upload a PDF, TXT, or Markdown file, import an explicitly selected Google Drive file from an owner connection with `drive_read`, or select previously synced Canvas coverage text. The owner-scoped `GET /v1/class-sessions/{classId}/canvas-sources` picker returns only coverage entities for the class's exact course whose Canvas source facts, locator course path, paired connection, expiry, and course mapping are valid. The user can import only a listed entity using its connection and entity IDs; the server reads title/instructions facts itself and pins their source revision and content hash. Canvas imports materialize as course-scoped plain-text references; the worker rechecks the connection, source revision, hash, NeedInfo state, and lease before materialization, indexing, and attachment. If the source or connection changes during import, the intake fails safely and the unattached material is marked deleted. Assignments, due dates, Canvas files, and remote URL fetches are out of scope. URL fetches accept readable HTML/plain text/Markdown up to 2 MiB, validate every redirect, pin each connection to a DNS-validated public IP while retaining the hostname for TLS checks, and enforce a 25-second total deadline. Files up to 50 MiB use the direct streamed endpoint. Larger PDF/TXT/Markdown uploads are resumable up to 500 MiB through an owner-scoped upload session with 8 MiB immutable parts, a durable part ledger, 24-hour sliding expiry, and idempotent completion. Request parts are spooled to disk and written to immutable local/S3 objects; final assembly, checksum validation, object storage, and indexing use temporary files or bounded reads. The course preference default remains 250 MiB and can be raised by the learner to 500 MiB. Class imports retain their NeedInfo fence through part admission and completion. Original PDFs are streamed to the browser rather than buffered by the API. Extracted text remains subject to the existing 5,000,000-character index budget and PDFs to the existing 1,000-page/parser limits. Printed page labels and PDF bookmarks are exposed through the class reference pane, and index entries carry only approximate, explicitly marked text-location geometry when extraction fragments align. Blank-text PDF pages receive bounded English OCR (up to 20 pages per file and a 12-second timeout per page); confidence and OCR provenance stay distinct from embedded text, and low-confidence OCR is identified in the reference pane. Pages outside that OCR budget or with unavailable OCR still need visual review. The reader now uses continuous scrolling with only viewport-visible pages plus a two-page overscan rendered as canvases and selectable PDF.js text layers. A bounded page/text cache limits memory. Document-wide search submits explicitly, navigates matching pages, and searches only text exposed by PDF.js; image-only pages without a PDF text layer remain unsearchable in this reader, even when separate backend OCR supports material indexing. Text-span highlights are approximate when a phrase fits one span. Drive imports reuse the existing connector intake, accept PDF/plain text/Markdown up to 5 MB, and persist connection/file/hash provenance with untrusted-source classification; OAuth tokens and provider file bytes are never included in intake receipts. Intake IDs and client command IDs make retries idempotent; only one import can be active per NeedInfo, and status remains queryable after the class page reloads. Uploads and fetched/imported content enter the existing material indexer in a separate two-thread class worker pool. New imports are stored as references; only owner-authorized, same-course or personal, ready instructional materials can be attached, and answer keys and sample papers are excluded. An attachment retries only the matching materials window, so live notes continue independently. Failed imports stay visible with safe errors and can be submitted again. Imported page text and file passages remain untrusted source material, not executable instructions.

Migration 0066 adds owner/class-scoped `class_resource_intents` and owner/course-scoped `course_resource_preferences`. `GET /resource-connectors`, `GET /resource-intents`, and `GET/PUT /resource-preferences` expose typed connector metadata, current NeedInfo selections, and revision-checked course defaults. The Materials view lets a learner enable library, upload, public URL, Drive, and previously synced Canvas coverage sources, turn URL imports off, and set a file-size cap up to 500 MiB; the default remains 250 MiB. NeedInfo source actions are disabled until these preferences load and are checked again before attachment or import on the server. Intent selections store explicit source IDs/provenance and request hashes; the URL intent contains its host and hash, while the separate intake row retains the URL needed by the bounded fetch worker and receipts omit it. Blackboard and Moodle are registered as non-selectable adapter stubs. Connector access remains read-only, and external writes are disabled. Courses must be active and owned by the learner to change saved preferences; a class without a course uses the default policy but cannot persist course-level edits.

The class Materials view also has an optional, user-triggered YouTube search. The authenticated route verifies class ownership before calling YouTube Data API v3, returns only embeddable video metadata, and keeps `YOUTUBE_DATA_API_KEY` server-side. The player uses YouTube's privacy-enhanced `youtube-nocookie.com` host and leaves the returned video title and thumbnail visible. Search is unavailable until the deployment enables the YouTube Data API and configures the key in the backend environment. The feature does not download media or captions, and does not index the video into class notes.

The floating shell controls show elapsed time, saved slices, local/connected state and the captured audio level. Pause/resume capture, mark a moment, Stop, and reopen Class remain available while another workspace view is open. Stop releases microphone and computer-audio tracks immediately and persists final metadata independently of cloud completion. Pause processing is a separate control. Returning to Conversation or closing the canvas does not stop capture.

## History paging and retention

Quiz history returns 25 records by default and uses opaque keyset cursors ordered by immutable indexed creation time and quiz ID, so answering a quiz does not move it across an already-issued cursor. Session- and lesson-filtered pages use denormalized indexed lookup columns. Older pages are available from quiz and lesson practice views. Session snapshots resolve the active quiz/review from indexed status and session metadata, with direct pointer validation when a pointer is available. Quiz challenges load only children of the requested quiz; persistent-gap detection uses an indexed join and selects the latest three independent attempts. The mobile Classes list also pages by `(created_at,id)`. Migration 0061 adds and backfills these lookup/index fields. Both legacy and indexed synthesis retries page through at most 100 nodes per durable outbox transaction, persist their cursor in the package, and resume after processing pauses.

Completed recordings with `keepAudio:false` remove server audio objects after transcription while preserving their note and transcript. A durable batch worker deletes up to 100 objects per job page, advances an indexed sequence cursor, and schedules the next page transactionally. Transient failures use the existing job retry policy; terminal failure stays visible and the owner can retry. Owners can also delete retained server audio from a completed recording while keeping notes/transcript. The audio endpoint returns an explicit removed response after deletion. Capture setup can be cancelled while permissions or local storage are pending; each audio source is monitored as soon as it is acquired, and cancellation during manifest creation removes an empty local recording. Cleanup polling stops on terminal states.

Course Classes reopen the class workspace. A link of the form `/s/{sessionId}?class={classId}` restores the correct conversation and canvas, including after chat restoration. Reopening on another device is read-only with respect to microphone capture. Device/epoch headers fence class chunk admission; mid-session device handoff is intentionally unsupported in this version.

## Durable processing

Migration 0048 adds `class_sessions`, `class_input_windows`, `class_output_versions`, and `class_session_events`, with owner indexes and recording/class cascading relationships. It is additive and leaves the lecture audio/transcript tables authoritative. Migration 0050 repairs two missing scheduling columns in installations created from an earlier revision of the existing worker schema; it preserves responsibility rows. Migration 0055 adds owner-scoped resumable material upload sessions and a per-part checksum ledger; class-bound sessions also retain their class and NeedInfo intake identity. Migration 0056 adds the compound owner/class/creation-order index used by bounded output keyset pages. Migration 0057 moves active and staged transcript/note membership into an indexed owner/class/set ledger; legacy arrays migrate lazily, rebuild completion switches set pointers atomically, and new revision packages keep frozen window membership in the ledger. Migration 0058 indexes synthesis-plan nodes by package, modality, level, and ordinal so tree construction can resume in bounded outbox pages. Migration 0059 indexes event revision boundaries and replay pages by owner and class.

Transcript, correction and finalization commits emit the class handoff into the existing transactional execution outbox. The coordinator consumes the handoff once and schedules `class_specialist` jobs through WorkflowStore in the dedicated In-Class worker. Local embedded installs run the same worker in its own thread; hosted paid deployments have an `openlearn-class` worker role. Local UI events only navigate. API BackgroundTasks do not create a second class-specialist queue. Revision-package readiness checks fetch only the three current package outputs rather than scanning all class outputs.

Policy changes and processing pause/resume take effect immediately through the epoch and cancellation fences. A durable `class.output.transition` outbox then reconciles at most 200 output records per transaction using an indexed creation-epoch keyset; outputs created under the new epoch are outside that transition snapshot and follow the current policy. Re-enabled notes backfill in 100-window keyset pages pinned to the active set and upper ordinal; a concurrent rebuild promotion restarts the page scan against the newly active set. Intermediate output deltas patch already visible rows, and the final event refreshes the bounded output page. The workspace disables conflicting controls while the transition is pending. Migration 0060 adds the output creation-epoch index.

Learner-facing output snapshots and deltas filter membership against the active transcript set only. Outputs from a staged correction remain hidden until the coordinator atomically promotes that set and emits its reset event.

A persisted contiguous completed-chunk watermark prevents reordered speech from being processed as earlier coverage. Each coordination transaction reads at most 1,000 chunk rows, then continues through the durable outbox when more contiguous completed chunks remain. The coordinator reads only segments beyond its cursor and carries the unsettled tail between handoffs. During explicit partial coverage, successful chunk transcription atomically increments persisted completed-count and coverage-revision counters on the class session. The coordinator compares those counters in O(1) instead of rescanning all completed sequence numbers on each partial-recovery page. When a previously missing chunk arrives, both base and note windows are rebuilt from the now-available transcript, and the package returns to full input coverage once every expected chunk is present. Migration 0067 backfills the counters for existing class sessions. Settled sessions with no new chunks, corrections, or coverage changes record a no-op metric and skip transcript rescans. Base windows settle at 30 seconds or 2,000 characters, with a 7,500-character grouping bound, prior passage context and a topic hint. Fast note windows settle at 12 seconds or 1,000 characters, and flush on a 1.2-second transcript pause or settled tail. Coordination pages through a durable segment/ordinal cursor in batches of 100, and final note settlement is paged at 100 note windows per transaction; the old 200-base-window and 500-note-window truncation ceilings are removed. Stable window keys include source wording/revisions and prior context. Durable learning jobs carry priority and creation-time ordering; class notes use priority 100 on the interactive queue, while material, practice and card work use the batch queue. The worker rotates outbox and specialist work across class targets, limits each class to two concurrent jobs per tick, and reserves batch capacity when background work is waiting. Outbox handlers run inside savepoints, retry with backoff up to five times, and then move to a terminal dead-letter state so one bad event cannot stall unrelated work. Migrations 0063/0064 add those worker controls. Lecture transcription uses a bounded four-worker batch with PostgreSQL `FOR UPDATE SKIP LOCKED` claims and a serialized SQLite fallback. Retry-wait jobs are eligible and prioritized ahead of slower batch analysis. Transcript publication validates the durable job lease and a chunk-attempt fence. Cross-chunk prompt context is omitted so normalized text does not depend on completion order; raw transcript remains immutable. Chunk admission and finalization lock the recording row and recheck the expected sequence count/duration inside the write transaction. Provider calls run outside publication transactions. Leases, processing epoch, retry attempt, current window and transcript revision are checked before publication. Stale results cannot replace current output.

Migration 0053 adds a bounded, owner-scoped processing-metrics ledger with a 2,000-sample retention limit per class. Capture ingest, transcription attempts, coordinator handoffs, specialist attempts, and first-note readiness record queue delay, run duration, outcome, and non-content counters in their durable transaction. The owner-scoped `GET /v1/class-sessions/{id}/metrics` endpoint reports sample counts, outcomes, counter totals, and p50/p90 queue, run, and end-to-end timings. The collapsed Processing diagnostics section in the class workspace fetches and displays those numbers only when opened. First-note end-to-end timing begins at server receipt of the first audio slice; it does not use the browser clock.

Enabled specialists produce:

- Notes: validated generated blocks with supplied transcript segment IDs. Evidence controls reveal the supporting wording and timestamps. Generated versions remain separate from the student's authored note body.
- Materials: existing retrieval over attached reference sources, excluding answer keys and unrelated courses; passages are labelled supplementary. Source access is rechecked on publication and every snapshot.
- Material NeedInfo: when retrieval returns no useful passage, a prompt is persisted in the class-session payload with the affected window and a short lecture query. The workspace can attach an existing owner-owned, course-eligible, ready material version or start a durable URL/PDF/TXT/Markdown/Drive/Canvas intake. Intake retries use a client command ID; active imports are unique per NeedInfo, and the class worker indexes sources separately from live notes. URL imports validate each redirect, pin the socket to a DNS-validated public IP while retaining the original hostname for TLS SNI/certificate checks, limit the complete fetch to 25 seconds and 2 MB, and omit source URLs/content from intake receipts. Drive imports use the existing owner-scoped connection and `drive_read` check, stable connector idempotency, and the 5 MB/type allowlist. Canvas selection is limited to already synced course coverage facts from the exact mapped course and a paired unexpired connection; revision/hash checks fence stale imports. Assignments, due dates, Canvas files, and remote reads are excluded. Ready eligible material is linked to the class conversation and matching is re-run for that window; no notes or transcript are overwritten.
- Practice: a pinned lecture-only QuizService activity with an independently checked first question prepared before readiness. Further questions, answering, feedback and challenges use the established quiz engine. Practice is off by default; when enabled, live practice quizzes are capped at one per ten minutes. Coverage itself creates no mastery evidence.
- Flashcards: grounded candidates in one private draft deck per class, keyed by input window. The class view supports answer/evidence reveal. Candidates remain unscheduled; this integration does not implement the broader flashcard editing/spaced-review feature.

Corrections replace current generated versions and mark previous quiz context superseded, while preserving presentations, answers, and student note edits. Generated note blocks record the recording, start/end time, cited segment normalization revisions, and a source revision; `reconciles` IDs link replacements to prior note outputs with overlapping transcript time ranges, and the workspace indicates when a note was updated. The workspace does not currently show prior note text side-by-side. Final complete or explicitly partial coordination marks only current, source-revision-matched note outputs settled and refreshes their output revisions for connected clients. Stale workers remain fenced by the current output/window check and by the transactional transcript revision recheck. Generated class note blocks do not write into the separately saved class note, which remains the student's editable copy. Failed outputs have independent retry controls; transient errors stay in a visible retrying state until the durable job reaches a terminal result, and the job/output transition is committed together. A new retry attempt fences a previously running transport retry. Processing cancellation retains ready content and prevents old jobs publishing after resume.

Live processing preferences can be changed from the class workspace without repeating setup. Turning a specialist off pauses its unfinished outputs and fences provider calls already in flight; ready content remains available. Turning it back on resumes retained note windows, while newly enabled materials, practice quizzes, and flashcard drafts start with the newest settled window and follow the preference for later windows. Practice still obeys its ten-minute cap. Preference changes use owner-scoped, revision-checked commands, and the event cursor tells connected clients to reconcile output state.

## Revision package and coverage

Stopping records expected chunks/duration and retains the existing capture integrity checks. Complete transcription schedules a summary, active-recall prompts and revision quiz. These publish independently; ready notes stay readable if another output fails. Enabled class draft cards remain available in Practice. Live practice is off by default and supports a 10-minute cadence, a 20-minute cadence, or one quiz at class end. The saved processing preferences also control note detail, professor reference following, provisional-caption visibility, transcript text size, and transcript autoscroll. Changing display settings does not interrupt processing; note-detail changes fence in-flight note jobs and apply to later notes, while already completed notes remain as generated. Audio retention can be changed while recording or transcription is active; disabling it removes server audio after transcription while preserving notes and transcript. After the recording archive is complete, the existing delete-audio action remains the way to remove retained audio. In-Class sessions skip the legacy lecture semantic post-pass so final package generation has one owner; once all expected audio is transcribed, the recording archive is marked completed with semantic stages labelled `class_managed`. A durable inbox delivery links back to the revision package through the shared notification table; workers do not send direct device messages.

The class preferences include a Buddy quiet switch. When enabled, it suppresses the revision-package inbox message for that class; generated notes, quizzes, recall prompts, and summaries remain visible in the class workspace.

Missing slices remain visible. Preparing available coverage requires stopped capture and an explicit partial-package command. Interruption, missing input, failed outputs, window limits or bounded synthesis are labelled completed-partial rather than complete. The persisted final-package row is a compact manifest of source-window IDs rather than a second copy of the entire transcript. For packages of at most six windows, summary and recall use a direct bounded call; longer packages create durable summary and recall leaves over every source window, then bounded fanout merge jobs. The plan is assembled through 100-window outbox pages; an indexed per-level ledger stores continuation state, and parent jobs can be scheduled as soon as their children are ready, even while later pages are still being built. The tree uses existing input-window, output-version, and job ledgers, survives worker restarts, retains original transcript citation IDs, and rechecks all package source revisions before publishing the root. Hierarchical results carry `evidenceMode=hierarchical`, the source-window count, and `boundedCoverage`; because synthesis compresses evidence, the class reports completed-partial rather than claiming unbounded completeness. The revision quiz still uses at most 12 evenly spaced transcript segments and 12,000 characters, so it remains explicitly sampled. Metrics retain available/sampled package-window and estimated-input counters. Provider usage metrics are separate: provider-reported token counts and costs are exact, absent token usage receives a labeled character-based estimate, and costs are unknown unless the provider reports them. Multi-call quiz and flashcard flows aggregate per-call usage; metrics are owner-scoped and retention-bounded. Transcript coordination now advances a durable segment-level cursor in transactions of at most 100 transcript segments, with an outbox continuation for the next page; final note settlement also processes at most 100 note windows per transaction. Silence flushing waits until the current transcript frontier, so pagination does not split note context as if the page boundary were a pause. The former 200 base-window and 500 note-window truncation ceilings are removed. Partial coverage recovery uses atomically maintained completed-chunk count/revision counters instead of a growing sequence list or repeated full scans (migration 0067). Active and staged transcript/note membership now lives in an indexed ledger, with compact set pointers in the session and atomic promotion when a rebuild finishes. New package manifests store a set ID rather than a lecture-length window array, and evidence/source checks page through indexed membership. Rebuild note reconciliation queries overlapping old ranges from the membership index; quiz invalidation derives deterministic class-practice quiz IDs from only retired transcript windows, avoiding an owner-wide quiz-table scan. Rebuild cutover still processes the retired-window pages in the coordinator transaction, so very large corrections may hold that transaction longer than the normal segment page budget.

## Rendering and recovery

The class canvas has Notes, Materials, Practice and Revision views. Selecting a supporting passage opens an inline reference pane beside the notes and keeps the class workspace mounted; the student can explicitly send that passage to the full Sources workspace. For an attached PDF, the pane requests the original file and a separate page manifest through authenticated owner- and class-scoped routes, opens the cited physical page in an authenticated, range-loaded PDF.js canvas reader, and keeps the extracted passage visible below it. The manifest includes printed page labels and up to 500 sanitized PDF bookmarks; a compact Contents list navigates by physical page index while displaying the printed label. PDF bytes are served inline with private/no-store headers; routes accept no storage key and exclude answer keys and sample papers. Indexing also stores per-passage normalized crop-box text-location estimates when pypdf visitor text can be monotonically aligned with extracted text. These estimates are explicitly coarse, fail closed for rotated pages or unmatched fragments, and are rendered only as explicitly approximate citation cues on the cited page. Blank-text PDF pages receive bounded English OCR; pages outside its 20-page budget or with unavailable OCR still need visual review. The reader now uses continuous scrolling with only viewport-visible pages plus a two-page overscan rendered as canvases and selectable PDF.js text layers. A bounded page/text cache limits memory. Document-wide search submits explicitly, navigates matching pages, and searches only text exposed by PDF.js; image-only pages without a PDF text layer remain unsearchable in this reader, even when separate backend OCR supports material indexing. Text-span highlights are approximate when a phrase fits one span. A shared `ClassActionRouter` handles source, note, quiz, flashcard, and guarded read-only HTTP(S) media opens. During live capture, an explicit chat request such as “open page 4”, “pull up chapter 3”, “show figure 2”, or “pull up the slide on cell division” can open a unique matching reference already present in the current class snapshot, but only from the conversation linked to that class. Page cues use physical page numbering; chapter and figure cues require a matching explicit label in the source title or retrieved passage. They do not search the full material library or infer unindexed labels. Explanation questions such as “show me how photosynthesis works” remain normal chat. The matcher is deterministic and only reads server-returned, owner-checked references; it does not call the website assistant, open arbitrary links, import sources, or issue external writes. A stopped class, ambiguous match or missing passage falls through to ordinary chat. Revoked material access also closes the open reference pane and invalidates pending PDF/manifest requests. Desktop uses the existing split canvas beside Buddy; mobile expands the same mounted workspace with Return to conversation. Quiet badges indicate practice availability. The web class workspace keeps an authenticated server-sent event (SSE) stream open over the durable event ledger; reset snapshots return the first 100 transcript passages and the first 100 visible class outputs. The client loads transcript passages by stable sequence/ordinal cursor and older results by a separate creation-time keyset cursor; output pages scan at most 2,000 candidate rows and carry an output-generation fence. Cited passages outside the loaded transcript page are fetched by ID. Each material source returned in a snapshot or result page is checked against its current owner-scoped attachment or matching-course access. Attach, detach, delete, and course-move mutations increment the output generation and emit a reset, clearing already loaded results; detached, deleted, out-of-course, and protected-role sources are omitted. Only root summary and recall package outputs are exposed; synthesis leaves and merge nodes remain internal. Initialized clients receive changed transcript segments and output versions with replayable cursor events; transcript corrections and output resets invalidate stale page cursors. Event IDs are stable per class and revision; clients reconnect with the numeric cursor or `Last-Event-ID` on the stream endpoint. The stream checks for new ledger entries every 750 milliseconds, sends heartbeat comments while idle, and drains bounded replay pages before waiting again. Cursor-ahead and missing-history gaps trigger a bounded transcript reset; corrections, recovered audio, and replacement revision packages send the required transcript/output resets. On disconnect, the browser reloads authoritative cursor snapshots before reconnecting with exponential backoff. There is no new WebSocket infrastructure. Older snapshots cannot overwrite newer cursor state, late responses from a previous class are ignored, and background updates do not move reading focus or scroll.

Each class snapshot also carries a monotonic material-access revision. The client closes any open reference and invalidates pending PDF/manifest requests when that revision changes, even if event-history pruning means the matching revocation event is no longer replayable.

The native mobile app has a Classes view that lists up to 30 owner-authorized class sessions and opens the same authoritative snapshot. It merges cursor deltas, recovers from gaps through server snapshots, subscribes to the authenticated class SSE stream with cursor replay and snapshot recovery, refreshes when the app returns to the foreground, and loads earlier outputs with the server's generation-fenced cursor. It is read-only: it shows current notes, retrieved material passages, NeedInfo prompts, practice prompts, and revision outputs without starting or controlling capture or importing sources. PDF viewing and reference navigation remain in the web/desktop class pane.

Opening saved class state does not request microphone permission. Account changes stop active capture; local manifests and upload recovery are owner-bound. Disconnected API/provider states retain local audio and ready generated output. The existing recording recovery/export flow handles interrupted saved slices and never restarts a microphone automatically.

Owner portability discovers the new tables through the existing ownership reflection. Import remaps class/session/window/output references and deck window keys, and imports class envelopes paused with no active jobs/capture. Deleting the recording cascades class rows, cancels its specialist jobs, removes the private draft deck and audio; shared quiz attempts remain historical records in their owned conversation. Full account erasure retains the existing comprehensive ownership cleanup.

## Validation and remaining acceptance

Automated checks cover stable/idempotent setup; foreign owner isolation; live outputs before Stop; checked shared quiz preparation; reordered/duplicate chunks and outbox handoffs; late audio recovery from partial coverage (including a guard against full completed-sequence rescans); source corrections during provider execution; expired leases; independent failure/retry; processing revision conflicts; explicit missing-coverage decisions; source access loss; export/import/delete; and HTTP capture-device fencing.

The current update was verified with 61 backend In-Class, lecture, workflow, migration, storage, and material tests passing; 2 tests were skipped. The In-Class suite includes partial-to-full late-chunk recovery and a SQL guard that rejects a full scan of completed chunk sequences. Frontend and hosted/device acceptance still need to be rerun for this architecture update.

Frontend checks cover no automatic microphone access, denial leaving no manifest, immediate microphone release at Stop, reconnecting with notes/focus intact, late snapshots for another class, separate processing pause, mobile workspace preservation and class restoration. Earlier TypeScript and desktop/mobile browser checks used a labelled demo class and deterministic provider fixture, without recording a real microphone or making paid generation calls. The current PDF.js production build could not be confirmed in this Windows environment because Vite failed to spawn while resolving React (`spawn EPERM`); no real microphone, live-caption provider, or paid generation acceptance is claimed.

Remaining environment acceptance: hosted PostgreSQL concurrency/leases and shared-device sync; long real recordings, storage-pressure and tab-close recovery; real provider latency/semantic quality; and native background/lock-screen capture. No live latency target or native capture reliability is asserted. Real class generation needs the application's configured transcription/text providers and an embedded or externally running existing agent worker.

Live-caption code is wired but has not been exercised with a real microphone or paid provider. Its deployment requires an OpenAI API key, migrations 0062 and 0065, and the explicit server feature flag. Authoritative class batch transcription is OpenAI-only with validated transcription models; general lecture recordings retain their configured provider behavior; provider latency and reconnect behavior during long classes remain unverified. Approximate recording-relative provisional-caption timing is persisted, but final reconciliation and tier-1 note generation are not implemented.
