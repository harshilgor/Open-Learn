# Open Learn In-Class Architecture Upgrade Plan

This plan extends the existing in-class implementation using the supplied coding handoff. The core class session, capture/recovery, durable specialist processing, quiz integration, revision package, and responsive workspace are already present. The work below targets the remaining product gaps in order, preserving the existing recording and revision fences.

## Completion update — 5 October 2026

The remaining implementation slices are integrated: caption-grounded provisional notes/reconciliation, course-library cue lookup, material-v2 indexing and background OCR, desktop lifecycle controls, mobile capture, metadata compaction and source accessibility fixes. See `docs/IN_CLASS_COMPLETION_STATUS.md` for verification and remaining environment acceptance. Open acceptance checkboxes remain open where actual device/hosted/AT checks have not been run.

## Product additions

1. **Low-latency, incremental class processing.** Separate fast note updates from slower material/practice work, flush notes on meaningful pauses, avoid rescanning and rescheduling the whole transcript, and make practice opt-in with a capped cadence.
2. **Efficient live updates.** Replace repeated full transcript snapshots with cursor/delta responses and paginated transcript recovery; retire the recorder bubble's independent full-transcript polling. Instrument capture, transcript, coordination, and first-note milestones so latency is measurable.
3. **Keep context usable during class.** Add an in-class reference pane that can stay mounted beside notes, with source/page navigation routed through a shared ClassActionRouter. Add media opens as read-only actions.
4. **Resolve missing resources gracefully.** Add a MaterialOrchestrator with library-first lookup, persisted NeedInfo prompts, and connector adapters for upload/URL first, then existing Canvas/Drive integrations. Resource acquisition must never block notes.
5. **Improve long-class correctness.** Page transcript coordination and recovery without dropping windows; use durable hierarchical summary and recall jobs across long timelines; reconcile final transcript revisions by recording, time range, and source revision; preserve student edits when generated notes are revised. Bound the remaining long-lived history scans.
6. **Make asynchronous updates dependable.** Persist event IDs and replay from a cursor, detect cursor gaps, and reload an authoritative snapshot after reconnect. Add fair per-class worker limits and backpressure so one busy lecture cannot starve other classes.
7. **Close platform and operations gaps.** Add a dedicated class worker and queue priority, enforce the supported class STT configuration, coalesce upload requests, and expose operational diagnostics. These code paths are implemented; hosted PostgreSQL/device concurrency and real capture still need environment acceptance.

## Design constraints and acceptance

- Keep the user's explicit Start/Stop and recording-consent behavior; never activate a microphone from navigation or a cue.
- Keep transcript-derived actions read-only or limited to a student-visible resource import. External writes require a separate user action.
- Material lookup, quiz, and card generation must not block live notes. Practice cadence defaults to off.
- Preserve owner, recording, capture-epoch, transcript-revision, worker-lease, source-access, and authored-note fences.
- No latency promise until measured on representative devices/providers. Report p50/p90 and stage breakdowns.
- Every API retry must be idempotent; persisted outputs/events are authoritative, and UI reconnect always has a snapshot recovery path.
- Acceptance for each phase includes focused unit/integration checks plus a live-flow check where the required provider/device is available. Never claim hosted/native acceptance without those environments.
